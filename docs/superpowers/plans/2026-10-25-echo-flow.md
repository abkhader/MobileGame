# Echo Flowing Time (Rebuild Round 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace swipe-per-move with "time moves when Pip moves". You steer with a floating joystick or with keys, hold ⏳ to wait, and hold ⟲ to rewind time. The world glides smoothly at Pip's pace and freezes when you let go. Rules, solver and levels stay unchanged.

**Architecture:**
- A pure-Dart `GameClock` turns a held intent into beats, driven by the Flame update loop's `dt`.
- A `FlowController` maps each beat onto the existing `GameController` (move, wait, undo) and handles bumps.
- New input widgets set the intent.
- `EchoBoard` interpolates from the clock's `beatProgress`, with a cached static layer.

**Tech Stack:** Flutter 3.47.7 / Dart 3.13.5, Flame 1.38, flame_audio 2.12.2, shared_preferences; `HapticFeedback` from `package:flutter/services.dart`.

**Spec:** `docs/superpowers/specs/2026-10-25-echo-flow-design.md`

## Global Constraints

- No changes to `packages/echo_core`, level grids, best scores or solutions. The only change in `tools/echo_solver` is the tip rule, which becomes 1-01..1-04 (Task 6).
- No new packages.
- Beat length:
  - Slow 300 ms, Normal 200 ms, Fast 140 ms (default Normal).
  - Rewind beats run at half the beat length.
- Joystick:
  - It spawns only in the lower 60 % of the board area, and not on buttons.
  - Dead zone 12 logical px.
  - The dominant axis wins; ties go horizontal.
- A blocked move never steps the game: no beat passes and no battery is used. A bump plays at most once per beat length.
- Rewind never crosses into a previous run.
- Exact strings:
  - `New echo · N left`, `Give up`
  - tip 1-01 `Drag anywhere to move Pip.`
  - tip 1-03 `Tap New echo. Pip starts over, and your echo repeats every move.`
  - tip 1-04 `Hold ⏳ to let time pass while Pip stays still.`
  - tip 1-02 is unchanged.
- Web keys:
  - Arrows and WASD move.
  - Space waits.
  - Z and Backspace rewind.
  - E starts a New echo.
  - R restarts.
- Reduce effects (setting) or OS reduce-motion disables trails, shimmer, tilt/squash and tint. Motion stays.
- Testing rule: never `pumpAndSettle` with a Flame `GameWidget` on screen. Use a fresh `PlatformAssetBundle()` per test and open repositories inside `tester.runAsync`.

  - `Claude-Session: https://claude.ai/code/session_01KmdnqmEPh6FUY7ByRnrW34`
- Work on branch `feat/flow`.

## Review Focus

1. **Holding a direction into a door that a ghost will open.** Pip must keep bumping without time passing; the player has to hold ⏳ to let the ghost arrive. A player who keeps pushing should see bumps, never a silent stall (Task 2).
2. **Releasing mid-glide.** Pip finishes gliding to the tile, then freezes. It never stops between tiles, and it never takes an extra beat (Task 1).
3. **Two thumbs at once.** Holding the joystick and pressing ⏳ or ⟲ together: the most recent press wins, and releasing it returns to whatever is still held (Task 3).
4. **The run ends while holding** (battery empty, auto-ending at 25). The clock stops and the intent clears, so the next run doesn't start moving on its own (Task 2).
5. **The app goes to the background while holding.** The clock stops and the intent clears. Coming back, the game is frozen, not running (Task 3).

### Task 2: FlowController — beats, bumps, rewind

**Files:**
- Create: `app/lib/game/flow_controller.dart`
- Modify: `app/lib/game/game_controller.dart` (add `isBlocked`)
- Test: `app/test/flow_controller_test.dart`, `app/test/game_controller_test.dart`

**Interfaces:**
- Consumes: `GameClock`, `IntentKind`, `MoveSpeed` (Task 1); the existing `GameController` (`move`, `undo`, `canUndo`, `state`, `lastEvent`).
- Produces:
  - `bool GameController.isBlocked(Move m)`:
    - True iff `m != Move.wait` and `Rules.step(state, m).player == state.player`.
    - Uses the rules' own door logic.
    - No `echo_core` change.
  - `class FlowController extends ChangeNotifier`:
    - `FlowController({required GameController game, required MoveSpeed Function() speed})`
    - `GameClock get clock`
    - `void setIntent(IntentKind kind, [Move? dir])`
    - `void advance(double dt)`
    - `double get beatProgress`
    - `GameState? get from` (the state before the current beat, for interpolation; null when idle or after a run change)
    - `ValueListenable<int> get bumps` (increments on each bump)
    - `ValueListenable<Move?> get bumpDir`
    - `bool get frozen` (true when the clock isn't running)
  - Beat handling:
    - **move:** if `isBlocked(dir)`, bump; otherwise `game.move(dir)`.
    - **wait:** `game.move(Move.wait)`.
    - **rewind:** if `game.canUndo`, `game.undo()`; otherwise stop. This is what stops rewind at the start of the run.
    - After any beat whose `lastEvent` is `runEnded`, `won` or `lost`, call `clock.stop()` and clear the intent.
