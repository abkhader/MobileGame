# Echo Levels and Sound Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship all 30 levels, each proven solvable by the solver and proven to need every run it allows, plus the game's sound.

**Architecture:** First the solver gets a sound pruning rule that makes realistic puzzle levels fast to verify. Then the solver CLI gains quality checks: a level must be solvable, its stored best score must be optimal, it must be unsolvable with one run fewer, and its run limit must sit inside its chapter's range. CI runs these checks on every push, so a level that fails any of them cannot ship. Levels are then designed one chapter at a time against those checks. Finally, sound is generated by a committed script (so it is ours, CC0) and played through a small `AudioService`, driven by game events.

**Tech Stack:** Dart 3.13 / Flutter 3.47.7, the existing `echo_core` / `echo_solver` / `app` packages, `flame_audio`, and Python 3 standard library (`wave`, `math`, `struct`) for sound generation.

**Spec:** `docs/superpowers/specs/2026-10-15-echo-game-design.md` (sections 2, 3.2, 4.3, 5, 8, 9)

**Also read:** `docs/superpowers/plans/2026-10-18-follow-ups-for-plans-2-and-3.md`. This plan covers its "Plan 3: do first" section (solver speed) and the stray overflow menu. The other items stay deferred to the release phase.

**Measured before planning:** a prototype of Task 1's pruning rule found the same best scores as today's solver and was about 7× faster on corridor-style levels (`two-door 3 runs`: best 14, 186 ms → 27 ms). Open-field 8×10 levels with 3–4 runs still exceed 20 million nodes. Levels must therefore be corridor-style puzzles. Any level the solver cannot verify within the budget fails CI and gets redesigned.

## Global Constraints

- **Level ids and files:** `C-NN`, where `C` is the chapter (1–3) and `NN` is 01–10. Files go in `app/assets/levels/<id>.json`, and the id must match the file name.
- **Chapters and run limits (spec 5):** chapter 1 (levels 1–10) allows 1–2 runs, chapter 2 (11–20) allows 2–3, chapter 3 (21–30) allows 3–4.
- **Tips:** only levels `1-01` to `1-03` have a `tip` (spec 5). No other level has one.
- **Grid (spec 3.4):** at most 8 columns × 10 rows. Characters `#` `.` `S` `E` `a`–`h` `A`–`H`. Each plate letter appears at most once, and every door letter has a matching plate.
- **Every level, enforced in CI:** solvable; stored `bestScore` equal to the solver's; stored `solution` replays to exactly `bestScore`; unsolvable with `runLimit - 1` runs (when `runLimit > 1`); `runLimit` within its chapter's range.
- **Solver budget:** default `maxNodes` 30,000,000. Each new level must pass `--check` in under 20 s on its own here, and the whole `app/assets/levels` check must finish in under 4 minutes.
- **Sound (spec 4.3):** a calm ambient loop plus short sounds for move, plate press, door open/close, run end and win. Assets are generated by a committed script and are CC0, recorded in `app/assets/audio/LICENSE.txt`. Separate Music and Sound effects toggles, which already exist and are saved.
- **New dependency:** `flame_audio: ^2.12.2` in `app/pubspec.yaml` only. No other new packages.
- **Testing rule:** never use `pumpAndSettle` with a Flame `GameWidget` on screen.

## Review Focus

1. **A level the solver can't decide** (budget exceeded) must fail `--check`; it must never pass silently. Pinned in Task 2.
2. **A level that is solvable with fewer runs than it allows** is too easy and must fail. Pinned in Task 2.
3. **A stored solution that doesn't win in the app's own engine** must fail the app's test suite as well as the solver CLI. Pinned in Task 2.
4. **Sound effects switched off** means no effect plays, even though music may still be on. Pinned in Task 6.
5. **Audio that fails to start** (for example a browser blocking autoplay) must never crash or stall the game. Pinned in Task 6.

### Task 1: Faster solver

**Files:**
- Modify: `tools/echo_solver/lib/src/solver.dart`
- Test: `tools/echo_solver/test/solver_test.dart`

**Interfaces:**
- Produces:
  - `Solved(this.bestScore, this.solution, {this.nodes = 0})` with a new `final int nodes` field: `Rules.step` calls used across the whole search.
  - The default `maxNodes` becomes 30,000,000. Every other signature is unchanged.

**Pruning rule.** This is sound: a ghost that never touches a plate or door can never affect any other actor.
- Track `interacted` for the current run. It becomes true when a recorded move's target tile is a plate or door, whether the move succeeded or was blocked.
- Never take the explicit `endRun` branch when `interacted` is false.
- If a `Rules.step` call auto-ended the run at tick 25 and `interacted` was false, discard that branch.
- Reset `interacted` to false at the start of every run.
- Why it is sound: a run that never targets a plate or door tile replays identically, because walls never change and its moves never involve a door. It never stands on a plate or in a doorway, so it changes no door and no other actor.

- [ ] **Step 1: Write the failing tests.**
  - **`differential: pruned solver matches exhaustive search`.** Use a reference search defined in the test file: a breadth-first search over complete action sequences by total ticks, with no pruning and no memo, that tries all 5 moves every tick and allows `endRun` at any tick including 0, capped at total score 9. Generate 300 random levels with `Random(42)`: width 4–6, height 2–4, runLimit 1–3, 0–2 plates each with 1–2 doors, one `S` and one `E`, and walls with probability 0.2. Skip any level whose grid `LevelLoader` rejects. For each level, `solve` must return Solved with the same best score as the reference when the reference finds one within the cap. When the reference finds none within the cap, `solve` must not report a best score at or below 9. Every `Solved.solution` must satisfy `replayScore(level, solution) == bestScore`. The test must run in under 30 s.
  - **`speed: two-door corridor`.** Grid `['a.S...b.', '#######A', '#######B', '#######E']`, runLimit 3. Expect `Solved` with best score 14 and `nodes < 200000`.
  - **`nodes are reported`.** On the 1-03 grid with runLimit 2, `(solve(level) as Solved).nodes > 0`.
- [ ] **Step 2: Run** `dart test test/solver_test.dart` in `tools/echo_solver`. Expected: FAIL on `nodes` and on the speed bound.
- [ ] **Step 3: Implement** the rule and the `nodes` field.
- [ ] **Step 4: Run** `dart test`, `dart analyze --fatal-infos` and `dart format --output=none --set-exit-if-changed .`, then `dart run bin/echo_solver.dart ../../app/assets/levels --check`. Expected: all pass, and the check still prints OK 4, 4, 5.
- [ ] **Step 5: Commit** `perf(solver): prune runs that cannot affect the level`

### Task 3: Chapter 1 levels (1-04 to 1-10)

**Files:**
- Create: `app/assets/levels/1-04.json` to `1-10.json`

**Interfaces:**
- Consumes: the CLI from Task 2 (`--write`, `--check`, `--report`).

**Design brief.** Each level is a small, readable idea, introduced in this order (one idea per level; combine earlier ideas later):
- **1-04:** one plate opens two doors.
- **1-05:** a door you must step through while still standing on its plate's neighbour (no-crushing timing, 1 run).
- **1-06:** first ghost that must wait on a plate for several ticks.
- **1-07:** a ghost opens a door you reach only later (timing).
- **1-08:** two plates, two doors, 2 runs.
- **1-09:** a dead-end path that looks right but wastes the ghost.
- **1-10:** chapter finale combining the above, 2 runs.

**Requirements:**
- Levels 1-04 and 1-05 use runLimit 1. Levels 1-06 to 1-10 use 2.
- Every name is unique, 1–2 words, with no tip.
- Grids are corridor-style. Walls make up most of the tiles; avoid open areas larger than 3×3.
- Best scores should generally rise across the chapter. Target 1-04 ≈ 5–8, rising to 1-10 ≈ 12–20.

### Task 6: Sound

**Files:**
- Create: `tools/sfx/generate_sounds.py`, `app/assets/audio/{ambient,move,plate,door,run_end,win}.wav`, `app/assets/audio/LICENSE.txt`, `app/lib/audio/audio_service.dart`, `app/lib/audio/flame_audio_service.dart`, `app/lib/audio/game_sounds.dart`, `app/test/support/fake_audio_service.dart`, `app/test/game_sounds_test.dart`, `app/test/audio_wiring_test.dart`
- Modify: `app/pubspec.yaml` (add `flame_audio: ^2.12.2` and the `assets/audio/` assets), `app/lib/app_services.dart`, `app/lib/main.dart`, `app/lib/screens/game_screen.dart`, `app/lib/screens/settings_screen.dart`, and every test that constructs `AppServices`

**Interfaces:**
- Produces:
  - `enum Sfx { move, plate, door, runEnd, win }`
  - `abstract interface class AudioService { Future<void> playSfx(Sfx s); Future<void> startMusic(); Future<void> stopMusic(); }` and `class SilentAudioService implements AudioService` (all no-ops), in `audio_service.dart`.
  - `class FlameAudioService implements AudioService`: preloads the five sfx files, loops `ambient.wav` at volume 0.5 via `FlameAudio.bgm`, and catches and ignores every error. It is not unit-tested.
  - `List<Sfx> soundsFor(GameState before, GameState after, GameEvent event)`, a pure function in `game_sounds.dart`:
    - `moved` → `[move]`, plus `plate` when some plate is occupied in `after` but not in `before`, plus `door` when `after.openDoors != before.openDoors`.
    - `runEnded` → `[runEnd]`.
    - `won` → `[move, win]`.
    - `lost` → `[runEnd]`.
    - `none` → `[]`.
  - `AppServices` gains `required this.audio` (`AudioService`).

**Sound generation.** `generate_sounds.py` uses the standard library only, with `random.seed(7)` so the output is identical on every run. It writes 22,050 Hz mono 16-bit WAV files:
- `move`: 60 ms soft click, a decaying 880 Hz sine.
- `plate`: 120 ms low thump at 220 Hz.
- `door`: 180 ms rising sweep, 300 → 600 Hz.
- `run_end`: 350 ms descending chime, 660 then 440 Hz.
- `win`: 600 ms rising arpeggio, 523 / 659 / 784 Hz.
- `ambient`: a 16 s seamless loop. Every partial completes an integer number of cycles in 16 s: a pad from 110, 165 and 220 Hz sines with slow amplitude swells, peaking at −12 dBFS.

Every file has short fades so nothing clicks. `LICENSE.txt` says the sounds were generated by `tools/sfx/generate_sounds.py` for Echo and are dedicated to the public domain (CC0 1.0).

**Wiring:**
- GameScreen keeps the state before each controller notification. After the notification it calls `soundsFor` and plays each sound only when `progress.sfxOn`.
- Music starts when Home first appears if `musicOn`. Startup is wrapped so that a failure (such as a browser blocking autoplay) is ignored, and Home's `Play` button calls `startMusic()` again so web music starts after the first tap.
- The Settings `Music` switch calls `startMusic()` or `stopMusic()` immediately after saving.

- [ ] **Step 1: Write the generator, run it** (`python3 tools/sfx/generate_sounds.py`), and verify each file with Python's `wave` module: 22,050 Hz, 1 channel, 16-bit, and durations within ±5 ms of the values above. Running it twice must produce byte-identical files (compare with `sha256sum`).
- [ ] **Step 2: Write the failing tests.**
  - `game_sounds_test.dart` covers each mapping. On the `1-02` grid, the move onto the plate gives `[move, plate, door]`, and a move along the floor gives `[move]`.
  - `audio_wiring_test.dart`, using a `FakeAudioService` that records calls and can be set to throw:
    - A swipe on level 1-01 plays `move`.
    - Winning 1-01 plays `win`.
    - With `sfxOn` false, a swipe plays nothing.
    - Turning `Music` off in Settings calls `stopMusic`, and turning it on calls `startMusic`.
    - A fake whose `startMusic` throws still lets Home and the Game screen work (Review Focus 5).
- [ ] **Step 3: Run** them. Expected: FAIL.
- [ ] **Step 4: Implement** everything above. Update every `AppServices` construction site, using `SilentAudioService` in existing tests.
