# Echo App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the playable Flutter app for Echo: screens, the neon Flame board, saved progress, ads with test IDs, hints, an Android release build, and CI that builds and tests it.

**Architecture:** `app/` is a Flutter package that depends on `echo_core` by path. Game rules stay in the engine. `GameController` (a `ChangeNotifier`) wraps `Rules`, keeps the undo stack and reports events. Flame only draws and animates. Flutter widgets handle input, the HUD, menus and ads. Services (levels, progress, ads) are plain classes passed down through constructors, with no state-management or routing packages.

**Tech Stack:** Flutter 3.47.7 (Dart 3.13.5), Flame, google_mobile_ads (with UMP consent), shared_preferences, integration_test, GitHub Actions with an Android emulator.

**Spec:** `docs/superpowers/specs/2026-10-15-echo-game-design.md` (sections 3.3, 4, 5, 6, 7, 8 and 9)

**Also read:** `docs/superpowers/plans/2026-10-18-follow-ups-for-plans-2-and-3.md`. This plan settles its Plan 2 items as follows:
- **Tick 25:** the controller reports a run change and the board snaps.
- **Undo:** the stack is cleared on every run change.
- **Lost state:** the final run is read from `currentRun`.
- **Hints:** a note is shown when the player's runs differ from the solution.
- **Levels:** they move into app assets.
- **SDK floor:** raised to ^3.11.0.

**Out of scope here:** sound and music playback, and levels 4–30 (Plan 3), Crashlytics and Play upload (the release phase). The Settings toggles are built and saved in this plan; Plan 3 makes them control audio.

## Review Focus

1. **App killed right after a win.** Stars must already be saved, because the completion is written before the Level Complete screen appears. Pinned in Tasks 2 and 6.
2. **Fast swipes during an animation.** Every swipe applies in order; no input is dropped or doubled. Pinned in Task 5.
3. **Android back button (predictive back, API 36) on the Game screen.** Returns to Level Select without changing progress. Pinned in Task 5.
4. **Rewarded ad closed early or failing.** No hint and no skip are granted, and the failure message is shown. Pinned in Task 7.
5. **The largest grid (8×10) on a small phone (360×640 logical px).** The board fits with square cells and doesn't overlap the HUD. Pinned in Task 4.

### Task 3: Game controller

**Files:**
- Create: `app/lib/game/game_controller.dart`
- Test: `app/test/game_controller_test.dart`

**Interfaces:**
- Consumes: `Level`, `GameState`, `GameStatus`, `Rules`, `Move`, `Scoring` (echo_core)
- Produces:
  - `enum GameEvent { none, moved, runEnded, won, lost }`
  - `class GameController extends ChangeNotifier`, with constructor `GameController(this.level)` and:
    - `GameState get state` and `GameState? get previous`. `previous` is the state before the last `move`; it is `null` after `undo`, `endRun`, `restart` or a run change, which tells the board to snap.
    - `GameEvent get lastEvent`
    - `bool get canUndo` (playing, and the current run has at least one move)
    - `bool get canEndRun` (playing and `state.tick > 0`)
    - `void move(Move m)` (ignored unless playing), `void undo()`, `void endRun()`, `void restart()`
    - `int? get stars`, which is `Scoring.stars(score: state.score, best: level.bestScore ?? state.score)` when won, else `null`
  - **Events:**
    - `move` sets `moved`, then `runEnded` if `runIndex` grew (the automatic end at tick 25), `won` if won, or `lost` if lost.
    - `endRun` sets `runEnded` or `lost`.
    - `restart` and `undo` set `none`.
    - Each call notifies listeners once.
  - **Undo stack:** holds the states of the current run only and is cleared whenever `runIndex` changes or the game ends.

  - **Moves and undo:** on `['S..E']`, `move(right)` gives player `(1,0)`, `lastEvent == moved`, `previous!.player == (0,0)` and `canUndo == true`. Then `undo()` gives player `(0,0)`, `previous == null` and `canUndo == false`.
  - **Win:** on `['S..E']` with `bestScore: 3`, three right moves give `lastEvent == won` and `stars == 3`. Another `move` changes nothing and doesn't notify.
  - **End run:** on `['aSAE']` with runLimit 2, `canEndRun` is false at tick 0. After `move(left)` it is true. `endRun()` gives `lastEvent == runEnded`, `state.runIndex == 1` and `canUndo == false`, so undo can't cross a run.

  - **Lose:** on `['aSAE']` with runLimit 1, `move(left)` then `endRun()` gives `lastEvent == lost` and `state.currentRun == [Move.left]`.
  - **Restart:** gives `GameState.initial`, `lastEvent == none` and an empty undo stack.
  - **Notifications:** each action notifies exactly once (count with a listener).
